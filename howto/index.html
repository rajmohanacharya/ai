RajAIAssist · User Guide

Local AI with Unlimited Usage, Complete Privacy, and Full Control

Getting started

RajAIAssist is a text-based AI workspace that runs the selected language model in a temporary private cloud runtime controlled by Raj. The permanent web address is https://rajmohanacharya.github.io/ai/.

  1. Open the permanent RajAIAssist web address.
  2. Paste the current runtime access key shared by Raj.
  3. Select Unlock RajAIAssist.
  4. Confirm the service status shows the model as available.
  5. Start a new conversation or ingest files for the current browser session.

A runtime access key is temporary. A key from an older runtime may no longer work. Keep the key private and use Remember key on this browser only on a trusted personal device.

Availability and offline messages

The GitHub Pages interface remains available even when the AI runtime is stopped. When the backend, model, or tunnel is unavailable, RajAIAssist displays Ask Raj to start AI.

Use Check AI status after Raj confirms the service has started. Refresh the page if the endpoint was recently republished. An online manifest means the browser has a current signed backend address; it does not guarantee that the temporary compute runtime will stay available for a fixed duration.

Conversations and session isolation

Each browser conversation has its own random session identifier, chat history, and ingested-file index. Use New when changing to a substantially different task. Deleting a conversation removes its server-side session history and current-session files.

Guest access is limited to the selected model, public help, and files uploaded within the current session. Guest sessions do not use Raj's personal knowledge or administrative material.

File Ingest

The file picker accepts multiple files in one selection. Upload only material needed for the current task and wait until each file is indexed before asking the question.

RajAIAssist can extract text from common documents, spreadsheets, presentations, email, notebooks, source code, logs, archives, and images through OCR. Unsupported or opaque binary files may be stored as metadata-only records. Files are treated as untrusted reference data and are never executed.

Mention important filenames in the prompt, for example: Compare application.log with config.yaml and identify the most likely root cause.

Screenshot paste and OCR

Use the screenshot paste area to add a clipboard image to the current session. The text model receives OCR text extracted from the image, not full visual understanding of every pixel. It may read visible text, but it may not reliably interpret colors, layout, arrows, faces, or graphical relationships.

Do not upload image or video for editing or generation. RajAIAssist v3.1 is strictly a text-output AI.

Response controls

Balanced is suitable for ordinary drafting, explanation, and brainstorming. Conservative asks the model to distinguish evidence, assumptions, and uncertainty more strictly. The output-length control sets a maximum; the model may finish earlier.

The interface offers 2K, 4K, 8K, and 16K choices. 8K is the default. After connection, RajAIAssist disables choices above the active model/context ceiling. Models with a 16K total context, including the added DeepSeek Coder 6.7B and StarCoder2 7B profiles, expose at most 8K output so enough room remains for the request, chat history, system instructions, and retrieved evidence.

Each completed assistant response also has a Download control. Export the response as ZIP, DOCX, PNG, Markdown, HTML, or text. ZIP includes the complete response and separately extracted fenced-code files where possible. Downloads do not execute model-generated code.

Longer output is useful for complete scripts and detailed analysis, but it takes more time and uses more context. Always verify important facts, calculations, commands, and generated code.

Recommended prompt formula

A strong prompt states five things:

  1. Task — what the AI must do.
  2. Input — which text or files to use.
  3. Context — why the task matters and relevant background.
  4. Constraints — rules, exclusions, assumptions, versions, and limits.
  5. Output — the exact structure, tone, format, and level of detail required.

Example:

Task: Analyze application.log and deployment.yaml to identify the most likely cause of the outage.
Context: The error began immediately after release 2026.07.17.
Constraints: Use only evidence in the uploaded files. Separate facts from hypotheses. Do not invent missing timestamps.
Output: Timeline, ranked hypotheses, one verification command per hypothesis, remediation, and prevention actions.

Advanced prompts

Use these editable templates as starting points. Replace generic wording with the exact task, filenames, constraints, versions, and output format that apply to your work. The templates do not auto-submit and do not override your request.

Advanced prompt · Log and incident analysis

Act as a senior site reliability engineer. Analyze the uploaded logs and configuration files. Build an evidence-based timeline, identify the first abnormal event, rank the three most likely root causes, and give a verification step for each. Separate observed facts from inference. Cite the source label for every material claim. Finish with immediate remediation, permanent corrective action, and monitoring improvements.

Advanced prompt · Complete code generation

Create one complete executable implementation for the requested task. Output the complete code first inside one correctly labelled code block. Include every import, class, function, configuration option, validation path, error path, command-line entry point, and cleanup step. Do not use ellipses, TODOs, placeholders, or omitted sections. After the code, provide only prerequisites, one example command, verification steps, and material assumptions. Do not claim the code was executed unless it was actually executed.

Advanced prompt · Code review and correction

Review the uploaded code as a hostile production reviewer. Identify correctness, security, reliability, concurrency, performance, portability, and maintainability defects. Quote the relevant source location for each defect. Then provide one complete corrected replacement file, not a partial patch, and include tests or verification commands. Preserve intentional behavior unless a change is required to fix a documented defect.

Advanced prompt · Document analysis

Analyze the uploaded documents and produce: 1) executive summary, 2) key findings, 3) decisions and commitments, 4) risks and unresolved questions, 5) action items with owner and due date when available, and 6) contradictions between sources. Use only supplied evidence and cite source labels for every substantive section.

Advanced prompt · Professional writing

Draft a clear professional message for the stated audience and objective. Preserve verified facts, remove repetition, use a confident but courteous tone, and make requested actions explicit. Include a useful subject line. Do not invent names, dates, commitments, or approvals that were not provided.

Advanced prompt · Implementation plan

Create an operational implementation plan with scope, assumptions, prerequisites, phases, milestones, dependencies, owners, risks, mitigations, validation steps, rollback plan, acceptance criteria, and a concise first-week checklist. Distinguish required work from optional improvements.

Advanced prompt · Learn from first principles

Explain the topic from first principles for an intelligent beginner. Define essential terms, build the mental model step by step, show one practical example, identify common misconceptions, and finish with a short self-check exercise and answer key.

Advanced prompt · Compare options

Compare the proposed options using a decision matrix covering capability, quality, latency, cost, security, privacy, operational complexity, maintainability, failure modes, and migration effort. State assumptions, identify disqualifying constraints, and give a recommendation with conditions under which another option would be preferable.

Advanced prompt · Structured extraction

Extract the requested fields from the uploaded evidence. Return valid JSON using the exact schema I provide. Use null for missing values, do not infer unsupported values, retain source labels in a source field, and list validation errors separately from the extracted records.

Do's and don'ts

Do

  • Use the access key generated for the current runtime and keep it private.
  • State the objective, relevant input, constraints, and desired output.
  • Name important uploaded files and wait until indexing completes.
  • Start a new chat for a substantially different topic.
  • Use Conservative mode for high-impact factual, technical, or operational work.
  • Review and test important facts, math, commands, and code before relying on them.
  • Remove secrets, personal identifiers, and unnecessary sensitive content before upload.

Don't

  • Do not share the runtime key publicly or store it on an untrusted device.
  • Do not upload passwords, tokens, private keys, one-time codes, or confidential material without authorization.
  • Do not upload irrelevant files merely because the picker accepts them.
  • Do not assume OCR is equivalent to full image understanding.
  • Do not upload image or video for editing or generation; this is strictly a text-based output AI.
  • Do not treat generated code, medical guidance, legal guidance, financial guidance, or safety-critical instructions as verified without qualified review.

Privacy and access boundaries

The browser sends prompts and current-session files to the active RajAIAssist backend. Guest keys cannot access Raj's private owner context or the Administrator Manual. Owner-only capabilities are enforced by the backend and are not granted merely by changing browser fields or request parameters.

Do not treat a public web address as proof that the AI is public. Access still requires a current signed endpoint and a valid runtime key.

Important limitations

  • The compute runtime is temporary and may become unavailable without notice.
  • Model quality, speed, and context capacity depend on the selected model and runtime.
  • File extraction and OCR can omit formatting or content.
  • RajAIAssist does not provide image or video generation/editing in v3.1.
  • Answers can be incomplete or wrong. Verify high-impact output independently.
