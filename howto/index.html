Getting started

Open https://rajmohanacharya.github.io/ai/.
Paste the current guest or owner runtime key shared by Raj.
Select an output length and reliability mode.
Upload relevant files or paste a screenshot when needed.
Ask one focused question, review sources, and verify important results.
The guest key supports chat and current-session files. The private owner key additionally enables the Personal Knowledge Vault. Never share the owner key.

Reliability

Balanced is suitable for brainstorming and creative work. Conservative is the recommended default for factual, technical, and document questions.

No language model can guarantee zero hallucinations. Check source labels and independently verify important facts, calculations, commands, health guidance, and generated code.

Files and screenshots

  • Select multiple files in one operation.
  • Wait until each file displays a chunk count before asking questions.
  • Name the exact file in the prompt when several files are attached.
  • Paste screenshots with Ctrl+V while the prompt box is focused.
  • OCR is text extraction, not complete visual understanding. Arrows, colour, spatial layout, faces, and chart geometry may be missed.
  • Large books and archives require structured compilation rather than one-shot summarization.
Using only application.log and deployment.yaml, identify the first failure, the likely cause, and the safest verification commands. Cite every conclusion.

Personal Knowledge Vault

The owner Vault is canonical on Zorin OS. When Raj starts a runtime, the compiled Vault is uploaded to temporary Colab storage. Runtime-created memories, OCR results, and compiled data are periodically pulled back to Zorin.

  • Guest users cannot access the Personal Vault.
  • Use from vault: collection-name to restrict retrieval.
  • Use an exact label such as [vault:projects:file.pdf#c12 p8] for precise evidence.
  • AI-suggested memories require owner approval.
  • Do not store passwords, tokens, private keys, OTPs, or banking credentials.

Sessions and privacy

Each browser profile receives a random session ID. Different devices or browser profiles normally have separate chat histories and session files, even when they use the same guest key. Two tabs in the same browser profile share the same session.

The backend owner can access application data and Vault content. Do not upload sensitive or regulated data unless you are authorized to process it through this service.

Prompt etiquette

Task: [exact outcome]
Files / Input: [specific files, data, or examples]
Context: [audience, situation, purpose]
Requirements: [mandatory details]
Constraints: [versions, budget, limits, exclusions]
Output: [script, table, checklist, report, email, etc.]
Validation: [assumptions, evidence, tests, risks]
  • Ask one focused question per request.
  • Use full names and exact identifiers instead of vague pronouns.
  • State whether outside knowledge is allowed.
  • For code, request complete files, tests, validation commands, and rollback.
  • For documents, request citations and an explicit abstention when evidence is insufficient.

Do's and don'ts

Do

  • Keep runtime keys private.
  • Use Conservative mode for factual work.
  • Name relevant files and Vault collections.
  • Review citations.
  • Test generated code in a safe environment.
  • Start a new chat for an unrelated topic.
  • Remove unneeded session files.

Don't

  • Do not upload credentials or secret keys.
  • Do not blindly run shell, SQL, or infrastructure commands.
  • Do not assume confident wording means correctness.
  • Do not expect continuous 24/7 availability.
  • Do not use remembered keys on a shared browser.
  • Do not treat OCR as full image understanding.

Advanced prompt library

Select a template, copy it, replace every bracketed field, and keep only requirements that apply.

Production code generation
Act as a principal software engineer, security reviewer, and test engineer.

Task: Build a complete production-ready [LANGUAGE/FRAMEWORK] solution for [REQUIREMENT].
Files / Input: Use [FILES] as the source of truth.
Environment: [OS, VERSIONS, DEPENDENCIES, DEPLOYMENT TARGET].
Requirements: Include all imports, configuration, validation, timeouts, error paths, structured logging, safe cleanup, tests, and an executable entry point.
Constraints: Do not invent fields or APIs absent from the evidence. Do not use TODOs, ellipses, pseudo-code, or omitted sections.
Output: Complete files first, then exact install/run/test commands, expected results, rollback, assumptions, and limitations.
Validation: Silently review syntax, undefined names, scope, counters, serialization, concurrency, security, and failure handling. Do not claim execution unless it occurred.
Incident root-cause analysis
Act as a principal site-reliability engineer and incident commander. Use only the supplied logs, metrics, traces, configuration, deployment records, and tickets.

Inventory evidence and gaps. Normalize timezones, clock skew, ingestion delay, duplicates, sampling, and out-of-order events. Build a timestamped timeline. Separate verified facts, strong inferences, weak hypotheses, and unknowns. Identify trigger, proximate cause, systemic root cause, contributing conditions, propagation path, blast radius, detection gaps, mitigation, recovery, and validation.

Cite filenames, timestamps, IDs, hosts, and representative messages for every material claim. Rank hypotheses with evidence for and against each one and specify the exact test needed to confirm or reject it. Do not treat correlation as causation or invent evidence.

Output: executive summary, impact, evidence inventory, timeline table, causal chain, hypothesis matrix, containment, remediation with rollback, prevention, monitoring improvements, and unresolved questions.
Evidence-grounded document Q&A
Use only the retrieved content from [FILE OR VAULT COLLECTION].

Question: [SELF-CONTAINED QUESTION]

Rules:
1. Cite every material factual claim with the supplied source label.
2. Separate explicit evidence, reasonable inference, interpretation, and unknowns.
3. Do not use outside knowledge unless explicitly requested.
4. Do not invent page numbers, quotations, identifiers, events, or missing content.
5. When the evidence is insufficient, say: “I could not establish this from the available evidence.”
6. Suggest a more specific follow-up using the filename, chapter, date, ID, event, or terminology that would improve retrieval.

Output: direct answer, evidence, sources, inference, confidence, and missing evidence.
Long book or research corpus
Act as a source-grounded long-form reading assistant for [BOOK/CORPUS]. Do not pretend the complete work fits in one request.

First audit extraction coverage, chapter/section structure, missing pages, OCR quality, and available source labels. Process one coherent section at a time. Maintain a compact ledger containing section, status, summary, entities, timeline events, themes, and sources. Never mark a section complete without evidence.

For follow-up questions, search the named character, event, chapter, concept, or source label. Do not use pretrained knowledge of the book or adaptations. If evidence is missing, abstain.

End each response with an exact self-contained next prompt naming the next section. Produce a whole-work synthesis only after the ledger shows complete coverage.

Career, CV, and interview
Act as a senior career strategist and ATS-aware CV editor.

Target role: [ROLE]
Location/market: [MARKET]
Files: [CV, JOB DESCRIPTION, PORTFOLIO]
Goals: [GOALS]

Map each requirement to verified experience. Do not invent employers, skills, dates, certifications, metrics, or achievements. Identify gaps and ask for missing evidence. Produce: role-fit analysis, keyword matrix, rewritten CV sections, quantified bullet suggestions clearly marked when confirmation is needed, LinkedIn changes, interview questions, STAR story outlines, and a 30-day job-search plan. Separate current market facts that require live verification.
Travel plan

Dates: [DATES]
Travellers: [DETAILS]

Provide a day-by-day itinerary, realistic travel time, budget categories, packing and documentation checklist, contingency options, and what must be verified live.
