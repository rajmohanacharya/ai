How to use RajAIAssist

RajAIAssist connects the public interface to a temporary notebook runtime that hosts local models. The model request and private workspace stay inside that runtime; the public page contains no model weights, private files or runtime keys.

Important: “Unlimited Token” describes segmented long-form continuation and persistent history. Each local model still has a finite context window, output limit, memory requirement and runtime-session limit.

1. Start the runtime

Run the supplied notebook from top to bottom. The final cell starts the local model server, application backend and temporary secure endpoint. Keep that final cell running.

The output prints two separate keys:

Owner runtime key: ...
Guest runtime key: ...

Never share the private master secret or repository update token.

2. Choose the correct key

Owner key unlocks persistent threads, private datasets, private uploaded files, artifacts, Code Studio, Research, Media Studio and snapshots.

Guest key unlocks temporary model chat only. Guest messages are not written to the server and guests cannot access private threads, files, datasets, summaries or artifacts.

3. Persistent owner threads

Create one thread per project. Use pinned context for permanent rules and the durable summary for current decisions and progress. Uploaded documents and generated artifacts remain linked to the selected thread.

The runtime retrieves only relevant excerpts plus recent conversation instead of putting the complete lifetime history in every prompt.

4. Model profiles

  • Smart: Qwen3 8B for everyday assistance and planning.
  • Coding: Qwen2.5-Coder 7B for software work.
  • Fast: Qwen3 4B Instruct for lower latency.
  • Quality / Reasoning / Coding Pro: optional larger models; the backend falls back to an installed baseline when unavailable.

5. Private Research

Research mode searches documents and datasets attached to the current owner thread. It does not browse the live web. Ask for citations and verify that claims include the supplied source labels.

6. Code Studio

Ask for complete files using filename-labelled code fences. Generated files become thread artifacts. The coding agent can write to the isolated project workspace and optionally run the restricted validation commands shown in the interface.

Review generated code before deployment.

7. Media Studio

Image generation uses a local SDXL pipeline. Video generation uses a local Wan text-to-video pipeline. Narration uses local Kokoro speech synthesis. Editing, PDF compression and movie assembly use local media tools.

Large video or image jobs can exceed the allocated GPU, memory, disk or session duration. Generate short test assets before full-resolution production.

8. Long-form output

Select 2K, 4K, 8K or 16K as the requested per-segment output ceiling. Enable long-form continuation for multiple segments. The selected model may stop earlier, use a smaller supported limit or require a continuation segment.

9. Save and restore

Use Save workspace now before ending a session. The runtime creates a private snapshot containing threads, messages, documents and artifacts, while excluding runtime keys, tunnel data and logs. Configure private persistent workspace credentials when automatic versioning is desired.

10. Troubleshooting

  • Key rejected: refresh the page and use the newest key printed by the active runtime.
  • Optional model missing: select Smart, Coding or Fast, or let the automatic fallback apply.
  • Runtime offline: restart the notebook and wait for the endpoint publication message.
  • Media model error: confirm model files are cached or allow the setup run to download them.
  • Guest cannot see files: this is expected and enforced by the backend.
